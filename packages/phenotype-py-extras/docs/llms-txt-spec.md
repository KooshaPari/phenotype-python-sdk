# llms.txt specification

This document describes the `llms.txt` format generated by the
`phenotype_py_extras.llms_txt` submodule.

## 1. Scope

`llms.txt` is a structured Markdown document that gives LLM-assisted code
search and generation tools a curated, machine-friendly summary of a
repository: install instructions, usage examples, the public API surface,
common errors with fixes, and pointers to upstream references.

## 2. Public API

```python
from phenotype_py_extras.llms_txt import (
    LlmConfig,           # dataclass
    load_config,         # (path: str | Path | None) -> LlmConfig
    render,              # (cfg: LlmConfig) -> str
    write_llms_txt,      # (cfg, out_path="llms.txt") -> Path
    validate_config,     # (cfg) -> None  (raises ConfigError)
    init_llms,           # (repo_dir, **kwargs) -> dict  (scaffold-kit)
    ConfigError,         # exception class
    cli_main,            # click command entry point
)
```

### `LlmConfig` fields

| Field           | Type                       | Required | Notes                                    |
| --------------- | -------------------------- | -------- | ---------------------------------------- |
| `repo_name`     | `str`                      | yes      | Display name shown in the `#` heading.   |
| `tagline`       | `str`                      | yes      | One-line description, shown as `> quote`. |
| `install`       | `str`                      | yes      | `pip install …` block.                   |
| `usage`         | `str`                      | yes      | `from … import …` block.                 |
| `public_api`    | `str`                      | yes      | Bullet list of public symbols.            |
| `common_errors` | `list[tuple[str, str]]`    | no       | `[(error, fix), …]` rendered as bullets. |
| `references`    | `list[str]`                | no       | URLs / paths rendered under "See also".  |

## 3. CLI

```bash
pheno-llms-txt --config pheno-llms-txt.yaml --out llms.txt
```

| Option    | Default             | Description               |
| --------- | ------------------- | ------------------------- |
| `--config`| (none, defaults)    | Path to YAML config file. |
| `--out`   | `llms.txt`          | Output path.              |

## 4. Conventions

- All sections are Markdown; `install` / `usage` / `public_api` are rendered
  verbatim (use a fenced block in YAML if you need multi-line content).
- `common_errors` is rendered as `- **{title}** — {fix}`.
- `references` is rendered as a flat `- ` bullet list under `## See also`.
- The output is deterministic given a config; no timestamps are injected.

## 5. Output contract

The generated `llms.txt` has the following section order (sections with
empty inputs are omitted):

1. `# {repo_name}` — H1 heading.
2. `> {tagline}` — blockquote tagline.
3. `## Install` — verbatim.
4. `## Usage` — verbatim.
5. `## Public API` — verbatim.
6. `## Common errors` — bullet list (optional).
7. `## See also` — bullet list (optional).

## 6. Quality bar

- `validate_config()` enforces: `repo_name`, `tagline`, `install`, `usage`
  non-empty; `common_errors[*][0]` (title) non-empty.
- `init_llms()` is idempotent: re-running against an existing config does
  not overwrite the user's edits.
- All file writes use UTF-8.
